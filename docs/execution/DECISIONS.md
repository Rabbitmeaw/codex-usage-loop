# 决策日志

## D-001 · 采用原生 SwiftPM macOS 应用

日期：2026-07-22

选择 AppKit 负责系统窗口和菜单，SwiftUI 负责呈现。理由是核心能力依赖 macOS 窗口、显示器和 ScreenCaptureKit API，无需跨平台抽象。

## D-002 · 通过本机 Codex app-server 读取额度

日期：2026-07-22

应用启动 `codex app-server --stdio` 并读取限额接口，不读取认证文件。接口是实验性的，因此解析必须容忍已知百分比字段的两种形式。

## D-003 · 无自有后端与数据库

日期：2026-07-22

应用是本机展示层，实时额度只保留在内存；仅使用 UserDefaults 保存用户界面偏好。这避免引入账户、同步和服务端隐私边界。

## D-004 · 两阶段宠物定位

日期：2026-07-22

先通过 CGWindowList 取得候选窗口，再在 macOS 屏幕录制授权可用时用 ScreenCaptureKit 细化宠物边界。仅在用户明确选择“启用像素级定位”时发起系统授权请求；权限不可用时必须回退到窗口几何估算。

## D-005 · 最小数据与最小权限

日期：2026-07-22

不上传数据、不保存截图。屏幕捕获仅为本机内存中的定位手段，不能成为应用可用性的硬依赖。不得在启动时自动弹出授权或应用内模态窗口；仅由用户明确触发屏幕录制请求，避免与 macOS 的退出并重新打开流程冲突。

## D-006 · 本地开发使用 ad-hoc 签名

日期：2026-07-22

构建脚本对开源 Release 使用 ad-hoc 签名使应用包可验证。`install.sh` 在本机存在 Apple Development 身份时优先使用它，以维持同一 Bundle ID 的 macOS 隐私授权；这不是 Developer ID 分发签名，也不改变 Release 的未公证策略。改为发布校验和、源码提交 ID 和安全使用说明，具体见 `docs/RELEASE_SECURITY.md`。

## D-011 · 开源 Release 不提供 Developer ID 签名或公证

日期：2026-07-22

项目将提供开源 Release 下载，但由用户自行确认下载来源与 Gatekeeper 提示。Release 必须提供 SHA-256 校验和和可追溯提交；不得建议用户关闭系统级 Gatekeeper。

## D-012 · 自定义内外环颜色进入下一批

日期：2026-07-22

计划为内环和外环分别提供原生 macOS 颜色选择器，使用 sRGB 值持久化，并提供恢复默认蓝绿的操作。实施前先补充颜色偏好模型与渲染测试。

## D-013 · app-server 限额映射独立为纯解析器

日期：2026-07-22

将限额字典映射抽离为 `RateLimitParser`，不依赖进程或 UI。客户端保留 JSON-RPC 传输与发布职责，测试直接覆盖解析成功、边界和值无效的情况。

## D-014 · MIT 许可与 GitHub Release 托管

日期：2026-07-23

项目采用 MIT License。官方公开仓库为 `Rabbitmeaw/codex-usage-loop`，首个 Release 是 `v0.1.0`，包含应用 ZIP、SHA-256 清单与构建元数据；仍不提供 Developer ID 签名或 Apple 公证。

## D-016 · 不自动更新，仅由用户打开官方 Releases

日期：2026-07-25

应用不在启动、后台或用户点击后自行请求版本信息，不下载或安装更新，也不引入更新框架。菜单只提供“在浏览器查看 GitHub Releases…”；用户点击后由 macOS 默认浏览器打开硬编码的官方 HTTPS Releases URL。这样提高兼容性修复的可发现性，同时保持拥有屏幕录制权限的 CodexUsageLoop 进程自身不主动联网。

## D-017 · 手动用量刷新与 pet 重测职责分离

日期：2026-07-25

“立即刷新”只请求最新用量，并显示刷新中或保留旧数据时的失败状态；pet 几何重测继续由“重新检测宠物位置/大小”独立触发。菜单不为手动刷新注册 ⌘R，因为快捷键事件由前台应用处理，CodexUsageLoop 作为 accessory app 无法在浏览器处于前台时可靠接收，且不应增加全局键盘监听。

## D-007 · 常驻卡片位置与双环演示互斥

日期：2026-07-22

开启“始终显示用量卡片”后，卡片按圆环位置固定：围绕 pet 时位于右侧，左侧或右侧圆环时位于正下方，并被限制在当前屏幕可见区域。演示双环只能在真实数据不是双环时启用，避免模拟值覆盖真实额度。

## D-008 · 不监听全局右键事件

日期：2026-07-22

移除悬浮层的右键菜单及 `NSEvent` 全局右键监听。应用控制功能均由菜单栏提供；全局输入监听会对其他应用造成不可接受的交互副作用。

## D-009 · 宠物精确定位按需执行

日期：2026-07-22

先选择评分最高的候选窗口，再请求 ScreenCaptureKit 精确定位。成功结果在容器几何不变时复用；未检测到宠物时按 5 秒退避，几何变化时最多每秒重新捕获一次。悬浮层轮询也调整为每秒一次，并跳过无变化的状态和窗口操作。

## D-010 · 菜单栏支持原色与单色图标

日期：2026-07-22

菜单栏图标提供原色蓝绿双环和单色 template image 两种模式，并持久化用户选择。单色模式交由 macOS 按菜单栏对比度显示白色或黑色，避免固定白色在浅色菜单栏中不可见。

## D-015 · Windows 版本采用独立原生 Win32 前端

日期：2026-07-24

保留现有 SwiftPM/macOS target，不对 AppKit 与 ScreenCaptureKit 实现做跨平台
重构。Windows 版本使用独立的 .NET 10 / C# 项目，以 Win32 窗口、User32、
GDI+、Shell API 和注册表实现平台层；透明叠加层采用
`WS_EX_LAYERED` 与 `UpdateLayeredWindow` 的预乘 Alpha 位图，不使用颜色键，
也不引入 WinUI、WPF、WinForms、Electron、Qt 或第三方 GUI/JSON 库。

Windows 进程使用 Per-Monitor V2 DPI awareness，内部几何统一采用物理像素。
Codex pet 优先通过 `.codex-global-state.json` 中的 GUI 几何状态定位，状态
不可读时回退到 Codex / ChatGPT 可见小窗口；状态文件只读取 pet 布局键，
不读取、解析或上传任何认证文件。配置使用当前用户注册表，实时额度只存在于
内存。
