# 宠物缩放后圆环定位偏差分析与修复

日期：2026-07-23

## 现象

用户调整 Codex pet 的显示大小后，圆环会出现轻微位置偏差，且直径没有随宠物实际大小更新。

## 结论

问题来自两处：宠物边界曾被透明容器的静态估算替代，且圆环的 SwiftUI 根视图未占满面板，造成渲染圆心相对几何圆心偏移。两处均已修复。

## 根因与证据

1. 授权屏幕录制后，`ScreenCaptureMascotLocator` 从 pet 窗口截图中提取实际不透明像素边界；该框是围绕 pet 模式的唯一几何输入。
2. 输入变化由窗口容器、pet 锚点与 placement 事件触发；每次变化仅采集 3 个短时样本并取中位数。稳定状态不截图，不存在稳态轮询。
3. `AroundPetRingLayout` 令圆心等于实测框圆心，直径等于实测框主尺寸乘已确认的比例；任务卡、容器中心与 placement 不参与此计算。
4. 屏幕录制未授权、截图失败或窗口暂不可见时才降级为容器估算；临时降级不会覆盖最后一次可信的实测边界。
5. `UsageRingsView` 的根 `ZStack` 显式占满 `GeometryReader` 画布，消除了此前约 9 pt 的渲染圆心偏移。

## 最终方案

1. 已授权时，直接使用实测 pet 像素边界，准确反映 pet 缩放。
2. 缩放、拖动、任务卡布局与左右边缘位置变化会触发一次受限采样；没有变化时复用缓存。
3. 三帧中位数抑制动画单帧边界噪声，避免圆环抖动。
4. 未授权时明确展示降级状态；用户可从菜单主动启用像素级定位，应用不会在启动时打断 macOS 的授权与重启流程。

## Codex 本地尺寸文件的可用性

可以读取 `~/.codex/.codex-global-state.json` 中的 `electron-avatar-overlay-bounds`。本机历史显示器记录里的 `byDisplayId` 已出现以下精确字段：

- 容器：`x`、`y`、`width`、`height`
- 宠物：`mascot.left`、`mascot.top`、`mascot.width`、`mascot.height`
- 绝对锚点：`anchor.x`、`anchor.y`、`anchor.width`、`anchor.height`

这组字段可直接给出宠物的真实边界，适合优先用于圆环中心与直径计算；它比固定比例和截图检测都更省电。

但当前活动显示器记录只保存了位置、显示器和 `placement`，没有 `mascot` 或容器宽高。因此不能假定每个 Codex 版本、每个显示器记录都提供实时尺寸。`byResolution` 记录当前也只有位置和布局，不能用于尺寸修正。

## 建议的分层读取方案

1. 首选当前活动显示器的 `byDisplayId` 记录；若其中的 `mascot` 与容器字段完整且通过屏幕范围校验，直接作为宠物边界。
2. 其次使用顶层 `electron-avatar-overlay-bounds` 的完整 `mascot` 或 `anchor` 字段。
3. 上述字段缺失时，保留已授权屏幕录制下的低频像素校准，自动得到真实尺寸。
4. 两者都不可用时，才回退到现有固定比例的几何估算，并标记为估算结果。

状态文件仍只作为触发重测与未授权降级的线索；它不会覆盖已测得的 pet 边界。

## 预期效果与代价

| 项目 | 结果 |
| --- | --- |
| 调整 pet 大小时 | 布局变化触发短时三帧测量，按实际边界更新 |
| 拖动 pet 时 | 仅在位置或锚点变化时重测，稳定时复用缓存 |
| CPU 与能耗 | 无稳态周期截图；每次变化仅进行短时受限采样 |
| 无屏幕录制权限 | 使用容器估算，不能保证缩放及边缘位置准确 |

## 验收

已验证普通位置、pet 缩放以及左右屏幕边缘位置：圆环圆心与尺寸均由实测 pet 边界驱动。
