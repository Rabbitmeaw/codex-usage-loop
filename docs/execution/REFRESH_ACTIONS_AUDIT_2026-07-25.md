# 刷新与重新检测能力审计

日期：2026-07-25

## 结论

“立即刷新”和“重新检测宠物位置/大小”均有真实调用链，不是空按钮。B23 已将两者职责分离：前者只刷新用量，后者只重测 pet 几何。两者都会启动异步工作，因此点击动作完成不等于新数据或新几何已经返回。

## 立即刷新

实际执行：

1. 调用 `CodexAppServerClient.refresh()`。
2. app-server 工作在专用串行队列中异步执行。
3. 进程已初始化时发送 JSON-RPC `account/rateLimits/read`。
4. 响应解析后回到主线程更新 `UsageStore.snapshot`，SwiftUI 随状态刷新。
5. pet 重测不会由该动作触发。

正常自动刷新每 30 秒只请求用量，不会主动清除 pet 测量缓存；pet 几何另有每秒一次的轻量检查。

### 反馈

手动请求期间显示“正在刷新…”。失败且已有旧 snapshot 时，卡片保留旧数据并显示“刷新失败，仍显示上次数据”；首次请求失败时仍显示实际错误信息。

菜单不注册 ⌘R。普通菜单快捷键由前台应用处理，浏览器处于前台时不会可靠送达 accessory app；应用也不为此引入全局键盘监听。

## 重新检测宠物位置／大小

实际执行：

1. `AppController.recalibrate()` 调用 `PetWindowLocator.reset()`。
2. reset 清除 ScreenCapture 定位器的：
   - 已测量结果；
   - pending 集合；
   - 上次输入；
   - 上次尝试时间；
   - 屏幕录制不可用的本轮状态；
   - 并推进 generation，使旧异步截图结果失效。
3. 随后立即执行 `updateOverlay()`，重新枚举系统窗口、选择 pet 候选并安排新测量。

reset 不会清除：

- `PetWindowLocator.lastMeasuredPet`；
- 已缓存的 `SCWindow` 列表；
- 屏幕录制授权请求记录；
- Codex 持久化状态。

保留 `lastMeasuredPet` 是稳定性策略：同一 pet window 的新截图尚未完成时继续显示旧实测几何，避免圆环先跳到估算值。它不代表按钮没有执行。

### 已授权时

在 macOS 14+ 且窗口有效时：

- 异步采集 3 帧；
- 帧间隔约 0.06 秒；
- 使用各边界分量的中位值；
- 新结果通常由下一次 1 秒定位轮询采用。

### 未授权或检测失败时

- 未授权时不截图，使用窗口几何估算或保留同 window 的旧实测。
- 捕获或检测失败时不写入新测量结果，并按约 5 秒退避重试。
- pet 候选临时消失时优先保留上次实测，再降级到持久化几何。

## 文档一致性

原用户手册中“立即刷新”同时重测 pet 的描述会混淆两个职责；“立即”和“清除定位缓存”也容易让人误解为同步完成及清空所有定位状态。B23 已把文案修正为：

- 用量请求与 pet 重测是相互独立的异步动作；
- 刷新状态和失败结果可见；
- 手动刷新不设置快捷键；
- 重新检测清的是像素测量与重试状态；
- 旧实测会保留到新结果完成；
- 授权后的新三帧测量通常在下一次 1 秒轮询生效。
